# dsh-cnb2api

在 DSH 里使用你自己 CNB 工作区的 **cnb2api** 网关。

真正的问题只有一个：**工作区地址会变，工作区还会被停掉**。平台每次重启工作区都换一个随机子域
（`<random>-<port>.cnb.run`），停掉后不再响应，也不会通知任何人。

插件因此提供两件事：后台盯住这两个变化，以及一个**地址永不改变**的本地网关
（`http://127.0.0.1:41729/v1`）。你把它填进 DSH 官方供应商一次，之后地址漂移、账号切换、
额度耗尽换人，全部发生在网关后面，配置不用再动。

> 文中的 `alice`、`acme`、`acme/gateway` 与数字均为示例。

---

## 1. 它做什么

| 落点 | 内容 |
|---|---|
| 供应商 | 自动写入 **设置 → 模型** 的 **CNB2API**（路由 `cnb-gateway`），选中即可对话 |
| 网关 | 固定基址 `http://127.0.0.1:41729/v1`（可改），地址漂移与账号切换藏在后面 |
| 工具 | `cnb2api_status` 看状态 · `cnb2api_start` 启动 · `cnb2api_quota` 查额度 |
| 路由 | `GET /cnb2api/status` · `POST /cnb2api/start` |
| 登录路由 | `POST /cnb2api/login/{token,orgs,repos,proxy-key}` —— 把令牌换成下拉选项、验证 PROXY_KEY |
| 备份路由 | `POST /cnb2api/backup/{export,import,webdav}` —— 导出/导入账号与设置，可存本地或 WebDAV |
| 界面 | **悬浮球**（可拖动、可关）+ **插件详情页**里的状态面板（含额度进度条）与配置表单 |

界面不占对话区：**悬浮球**浮在窗口角落，详细的**状态面板**在
**设置 → 插件 → CNB2API** 里。工作区状态是「需要时去看」的东西，不该在每个会话里常驻一行。

## 1.5 为什么不直接填工作区地址

因为两端都在动：

1. 工作区地址每次重启都换（`<random>-<port>.cnb.run`）；
2. DSH 自己的 Web 端口每次启动也会变。

所以「填一次永久有效」必须有一个固定入口。网关就是那个入口，它同时解决另外两件事：

| 需要 | 网关的做法 |
|---|---|
| 地址漂移 | 每个请求现取当前地址，不用改配置 |
| 多个账号 | 按可用性挑一个能用的；上游 402/5xx 时**同一请求内**换下一个 |
| 额度耗尽 | 失败的账号冷却 60 秒，期间排到最后（只降权，不排除） |

## 1.6 悬浮球

窗口角落一枚 44px 的球，用颜色回答「现在能不能用」。球面是一个**环形进度条**，
显示总额度已耗比例（0–100%，整数），鼠标悬浮看细节。

| 环色 | 含义 |
|---|---|
| 绿 | 可用 |
| 黄 | 额度用尽 / 正在启动 |
| 红 | 配置有问题（令牌、权限、仓库） |
| 灰 | 未配置 / 读不到额度（不画弧，不谎报 0%） |

百分比 = **已用 + 冻结**占总额的比例。冻结是预扣（见第 4 节），那一刻就已不可用，
只算 `used` 会严重低估消耗。

- **点一下**展开卡片：每个账号一行（圆点 + 名称 + 徽标 + 额度条）+ 启动按钮 + 「打开插件页」。
  卡片头部（刷新/关闭）与底部按钮固定，只有中间的账号列表滚动。
- **拖动**换位置（位移小于 4px 算点击），位置记在浏览器里。
- 挂在 `shell.overlay`——全窗口浮层本来是全穿透的，所以球只占自己那 44px。
- **开关**在配置表单的全局设置里（「显示悬浮球」）。这是浏览器偏好，点了立刻生效。

> 球只能待在窗口内：DSH 客户端插件运行在页面里，插件 API 没有创建桌面窗口的能力。
> 要真的浮到桌面上，得改 DSH 桌面端本身。

它**不**做三件事：不停工作区（重启要 30–90 秒且换地址）、不替你选仓库、不合并组织额度（CNB 不支持）。

## 2. 配置

在 **设置 → 插件 → CNB2API → 详情页** 里配置，每个账号按四步走：

```
① CNB 访问令牌      粘贴后点「验证并登录」
② 组织              下拉，来自这个令牌真正能访问的列表
③ 仓库              下拉，来自所选组织；标出「运行中」的已有工作区
④ PROXY_KEY         该仓库 .cnb.yml 中 env 的值
```

**为什么要先验证**：组织名和仓库名都记不住，手填错了还不会报错——插件只会静默接到
另一个仓库的工作区去。所以第 ① 步先用令牌换回身份与组织列表，第 ②③ 步都从真实数据里选。

- 组织列表合并三处来源（`/user/repos`、`/user`、`/user/groups`），单看任一处都会漏。
- 仓库列表标出「运行中」，因为组织里可能有好几个仓库，只有跑着的那个才是你要的。
- 令牌填成 `sk-` 开头时立刻点明「这是 PROXY_KEY，不是访问令牌」，不必等 CNB 回 401。
- 令牌一改就退回未验证态：旧的组织与仓库列表不再可信。
- PROXY_KEY 默认遮住，点「显示」可以核对——40 位密钥靠肉眼比对不现实。

三类凭据的差别：

| 凭据 | 用途 | 位置 |
|---|---|---|
| CNB 访问令牌 | 调 CNB OpenAPI：列工作区、读日志、启动 | CNB 头像 → 访问令牌 |
| 组织/仓库 | 地址与账号都按它确定 | ②③ 两步选出来 |
| PROXY_KEY | 网关转发时用作上游 `Authorization` | 该仓库 `.cnb.yml` 的 `env` |

### 令牌权限

| Scope | 用途 | 缺了会怎样 |
|---|---|---|
| `repo-cnb-trigger:r` | 读启动日志取地址 | **不可用**：取不到地址 |
| `account-engage:r` | 列出工作区 | **不可用**：找不到工作区 |
| `repo-cnb-trigger:rw` | 启动已停止的工作区 | 地址仍跟随，但停了不会自动拉起 |
| `group-resource:r` | 显示 AI credits 与核时 | 不显示额度；启动前不再拦截 |
| `repo-cnb-detail:r` | 优先从详情取地址 | 回退读日志，略慢 |

最小可用组合：`repo-cnb-trigger:rw` + `account-engage:r`。

### 其他设置

| 字段 | 默认 | 说明 |
|---|---|---|
| `models` | `deepseek-v4.1-flash` | 模型清单（逗号分隔），写进供应商供选择 |
| `checkSeconds` | 120（最少 30） | 巡检间隔 |
| `autoStart` | `true` | 工作区停止后是否自动拉起 |
| `branch` | `main` | 启动用的分支 |
| `port` | 9001 | 工作区里 cnb2api 的端口 |
| `gatewayHost` | `0.0.0.0` | 网关监听地址；`127.0.0.1` 仅本机 |
| `gatewayPort` | 41729 | 网关监听端口；被占用会自动顺延 |
| `gatewayKey` | 自动生成 | 客户端调用网关用的密钥；留空则自动生成 |
| `autoPublish` | `true` | 自动把基址/密钥写进「设置 → 模型」 |
| `lowCreditPercent` | 5 | 余额**警戒线**（%），低于此值时提示，账号照常用 |
| `creditFloorPercent` | 1 | 余额**保底线**（%），低于此值时**停止使用**该账号；0 表示不设保底 |
| `lowCreditMessage` | 空 | 提示文案模板，留空用默认句子 |
| `locale` | `auto` | 界面语言（auto 跟随浏览器）；工具输出 auto 用中文、显式 en 用英文 |
| `webdavUrl` | 空 | WebDAV 备份目标（目录或完整路径）；只填目录会自动补 `cnb2api-backup.json` |
| `webdavUser` / `webdavPassword` | 空 | WebDAV 账号；只存在本机 profile，**不随备份导出** |
| `autoBackup` | `false` | 保存配置后自动上传备份到 WebDAV（还原仍需手动）|
| `apiBase` | `https://api.cnb.cool` | CNB OpenAPI 基址（一般不用改，仅在 cordis.patch.yml 里） |

### 警戒线与保底线（两件事）

| | 警戒线 `lowCreditPercent` | 保底线 `creditFloorPercent` |
|---|---|---|
| 作用 | 提示 | **硬停** |
| 低于之后 | 照常接活，界面出一句提示 | 完全不派活：网关拒绝、不自动启动 |
| 默认 | 5% | 1% |
| 想关掉 | —（始终提示） | 设 0 |

保底线的意义是**给自己留一条退路**：任务可能在最后一步把额度吃穿，
留 1% 就能在超用之前停下来。代价是最后一个任务可能被拦下。

判定口径与「可不可用」一致：`可达 && 未标记故障 && 可用 ≥ 保底线`。
**额度查不到时不拦**——拿不到数字就断言「不够」，会把能用的账号挡在外面。

### 余额不足的提示文案（可自定义）

警戒线以下时，可以在「配置 → 全局 → 不足时的提示文案」里写自己的句子，
用变量插入真实数字：

```
{account} 额度告急：已用 {consumed}/{total} {unit}（{percent}%），仅剩 {remain} {unit}
→ qdirs/cnb2api 额度告急：已用 1157.7/1166 cr（99.29%），仅剩 8.3 cr
```

| 变量 | 含义 |
|---|---|
| `{account}` | 账号（org/repo） |
| `{used}` | 已结算消耗 |
| `{frozen}` | 预扣（冻结） |
| `{consumed}` | `{used}` + `{frozen}`，真实消耗 |
| `{remain}` | 账面可用（已扣预扣） |
| `{total}` | 总额（含赠送） |
| `{percent}` | 已耗百分比，两位小数 |
| `{threshold}` | 当前警戒线 |
| `{unit}` | 单位（`cr`） |

数字一律由插件算，**不要在文案里自己拼**：`used` 与 `consumed`、`remain` 与
`total − used` 的区别很容易搞反。写错的占位符会**原样保留**，方便你看见它。
同一句话里 `{consumed} + {remain}` 恰好等于 `{total}`（显示精度下自洽）。

配置页里每个变量都带一句说明，下方还有**实时示例**——按你正在输入的文案和一组
接近真实的数字渲染，不用保存就能看到效果。默认句子短版是「额度即将耗尽 · 请补额度」。

同一句话也会写进网关响应头 `x-cnb2api-credit-notice`（percent-encoded，因为
HTTP 头只能是 ASCII），供非 DSH 客户端读取。

### 账号备份与还原

配置页底部有「备份与还原」一栏，把账号和/或设置打包成一份 JSON，可存本地或 WebDAV。

- **备份内容可选**：只账号、只设置、或两者。账号含 `token/repo/proxyKey/branch/port`；
  设置含巡检、网关、警戒线/保底线、模型清单等。网关访问密钥 `gatewayKey` **不进备份**
  （本机凭据，换机应重新生成）。
- **默认口令加密**（AES-256-GCM，密钥由 scrypt 派生）。留空口令则导出明文 JSON ——
  里面是完整令牌，注意文件存放。口令错了会明确报错，不会给出半份数据。
- **还原是合并**：按仓库对齐，同仓库以备份为准、新仓库追加、现有其它账号保留。
- **本地**：导出下载 `.json`，导入选文件。
- **WebDAV**：填地址/账号/密码后可上传或下载并导入；请求由 Host 代发（WebDAV 普遍不带
  CORS 头，浏览器直连会被拦）。勾选「保存后自动上传」则每次保存配置成功后静默推一份备份，
  **还原始终手动**，不会自动覆盖本地账号。

### 配置页的组织方式

账号多、设置多时页面会很长，所以做了两件事：

- **账号卡可折叠**：每张卡左上角有折叠箭头；账号超过一个时，区标题旁还有
  「收起全部 / 展开全部」，一键把页面压成一行一个账号。
- **全局设置按组分段**：巡检 / 网关 / 余额与提示 / 其它，四段小标题，
  不再是一条长长的同质列表。

### 网关的安全边界

监听 `0.0.0.0` 等于把「花你的额度」开放给整个局域网，所以：

- **没有访问密钥就拒绝监听非回环地址**（不是警告，是启动失败）；
- 每个请求校验 `Authorization: Bearer <key>`，恒定时间比较；
- 客户端的密钥只用于访问本网关，上游一律换成工作区自己的 `PROXY_KEY`；
- 密钥首次运行自动生成并写回配置，重启不变。

局域网设备用插件页显示的 `http://<内网 IP>:41729/v1` + 访问密钥即可接入。

## 3. 状态怎么读

一个账号两件东西：**圆点**回答「能不能接住请求」，**徽标**回答「卡在哪一环」。

| 状态 | 含义 | 有启动按钮 |
|---|---|---|
| 就绪 | 在跑、地址通、额度够 | 否 |
| 额度用尽 | 组织 AI credits 归零：启动与请求都会失败 | 否（会说明原因） |
| 地址不通 | 在跑，但网关连不上 | 否 |
| 已停止 | 有工作区实例，没在跑 | 是 |
| 无工作区 | 该仓库从未建过 | 是 |
| 启动中 | 刚提交，等就绪 | 否 |
| 配置有问题 | 令牌、权限、仓库这类硬失败 | 否 |

**额度用尽压过「已停止」**：停机时额度也归零，光写「停止」会让人以为补个实例就能用。

颜色规则只有四条，全部收敛到「常态不报警」：

| 语义 | 颜色 | 用在哪 |
|---|---|---|
| 正常消耗 | 业务蓝 | 额度进度条 |
| 已用完 | 中性灰 | 进度条空槽、用尽行的文字 |
| 需要你注意 | 橙 | 只有「余额低于警戒线」那一句 |
| 真故障 | 红 | 只有「配置有问题」 |

地址默认打码（`860l****-9001.cnb.run`），因为状态常被截图分享；要看完整地址设
`CNB2API_SHOW_FULL_HOST=1`。

## 4. 额度怎么算（含「冻结」）

CNB 的额度接口分三个，字段口径不同，合起来才算得出一笔账：

| 字段 | 含义 |
|---|---|
| `total` | 总额，**已含赠送额度** |
| `used` | 已结算的消耗 |
| `frozen` | 预扣：工作区运行时占用的额度 |
| `remain` | `total − used − frozen` |

### 冻结不是押金，是预扣

实测（停掉工作区前后对比）：

| | 停止前 | 停止后 |
|---|---|---|
| used | 477.94 | **1124.33** |
| frozen | 642.71 | **0** |
| remain | 45.35 | 41.67 |

冻结归零的同时 `used` 涨了 646——不是退还，是**划账**。冻结那一刻就已经从额度里扣掉了，
停止时只是换个科目名。所以：

- **进度条用 `used + frozen`**，只算 `used` 会严重低估（上面那个时刻是 41% vs 真实 96%）；
- **`remain` 是唯一可以看「还能用多少」的数**，它已经扣过冻结；
- 界面把冻结标注为「预扣」，悬停提示「已从额度中扣除，停止工作区后计入已用，不返还」。

`quota.total` 已含赠送额度，算基数时要减掉，否则同一笔赠送被算两遍——这是最容易改坏的一处，
`test/quota.test.mjs` 专门盯着。

## 4.5 不白烧核时

cnb2api 是 AI 网关：组织的 AI credits 用尽后，它对每个请求都回
`402 [EXCEEDING_LIMIT] AI 积分已用尽`。这时启动工作区只会白等 30–90 秒并消耗核时，
所以启动前先查额度：

| 情况 | 行为 |
|---|---|
| 额度用尽 | 不提交启动，日志只记一次；额度恢复后巡检自动启动 |
| 额度查不到 | **照常启动**：拦住一个能用的，比放过一个注定 402 的更糟 |
| 余额很少但 > 0 | 照常启动，不提前拦截（但界面会按警戒线提示） |

## 5. 接入 DSH 模型供应商

插件**不实现 LLM 协议层**——那部分交给 DSH 官方的 OpenAI 兼容供应商
（`@deepseek-ai/dsh-llm-pi-ai`），它已包含请求/流翻译、图片编码、用量、重试与上下文预算。
自己再写一遍，等于把同一件事做第二遍，而 DSH 的每条隐性要求漏一个就是用户可见的故障。

所以插件只做一件事：把「固定基址 + 密钥 + 模型清单」写进官方那条配置。

```
插件（跟随地址 / 切账号 / 查额度）
        ↓
网关 http://127.0.0.1:41729/v1
        ↓
设置 → 模型 的 CNB2API（路由 cnb-gateway）
```

- 写入的是 `llm-pi-ai` 的 `providers.cnb-gateway`，**按路径写**，不碰你自己配的供应商。
- 密钥存进凭据库（引用名 `CNB2API_GATEWAY_KEY`），配置文件里只有引用名。
- 关掉「自动接入」开关就撤回这条路由。
- 模型清单来自配置里的 `models`（逗号分隔，默认 `deepseek-v4.1-flash`）。

### 自动接入为什么由状态接口驱动

写配置在 DSH 内部是 `hmr.runExclusive(...)`，而 HMR 用 `AsyncLocalStorage` 标记
「正在重载」的上下文。插件的 `apply()` 恰好跑在那个上下文里，标记会**沿整条异步链传播**
——`setTimeout`、`setInterval`、`appReady.onReady` 全都带着它，写配置一律被拒为
`HMR transactions cannot be nested`。

可靠的做法是由**请求处理**发起（HTTP 请求在网关服务自己的上下文里，是干净的）。
所以第一次打开插件页（或任何一次 `/cnb2api/status`）就完成接入。

### 网关响应头

每个转发的响应都带余额状态，客户端在对话开始前就能看到快到线了：

```
x-cnb2api-credit-remain: 19.28
x-cnb2api-credit-total:  1166
x-cnb2api-credit-low:    1        ← 低于警戒线
```

## 6. 常见现象

| 现象 | 原因 | 处理 |
|---|---|---|
| `401`（CNB） | 令牌无效或过期 | 重新生成访问令牌 |
| `401`（网关） | 访问密钥不对 | 用插件页显示的密钥 |
| `402 [EXCEEDING_LIMIT]` | 组织额度用尽 | 联系根组织管理员；期间不会自动启动 |
| `connection refused` | 网关没在监听或端口变了 | 看插件页的「网关」区确认端口 |
| 面板一直「识别中」 | 首轮还没跑完，或缺权限 | 看日志里的权限报告 |
| 徽标「配置有问题」 | 令牌、权限、仓库硬失败 | 状态行下面跟的就是具体原因 |

日志带账号前缀：

```
[cnb2api] [alice | acme/gateway] 工作区已停止 · 正在启动
[cnb2api] [alice | acme/gateway] 已提交启动 · 网关通常 30–90 秒内就绪
[cnb2api] 已接入「设置 → 模型」· cnb-gateway · http://127.0.0.1:41729/v1
```

## 7. 已知限制

- 两个账号指向**同一仓库**时共用同一工作区：地址与额度都是同一份。
- PROXY_KEY 按仓库保存：换仓库就要换密钥。
- 令牌与 PROXY_KEY 存在本机 profile 的 `cordis.patch.yml`，多人共用机器时注意文件权限。
- 冷启动 30–90 秒；网关的首次请求会等，之后走缓存。
- 升级插件后 HMR 会重载 entry，网关端口不变，但正在进行的对话可能被中断一次。

### 配置为什么能就地生效

设置页只接受 `.volatile()` 字段的写入。代价是 volatile 写入**不重启 entry**，
而 `apply()` 只在激活时构建账号数组——所以 `apply()` 自己按配置指纹对账：
新增账号接上巡检、移除的停掉定时器、换凭据的作废旧地址。少了这一步，
用户会看到「已保存」但工具里没有新账号。
